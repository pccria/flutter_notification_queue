# API Reference

This document outlines the public API surface of FNQ.

---

## 1. Design Philosophy

FNQ follows a philosophy of **Progressive Disclosure** and **Intent-First
Design**. Data intent (`AppNotification`) is decoupled from spatial rendering
(`NotificationQueue`), domain routing (`NotificationChannel`), and state
ownership (`NotificationController` & `NotificationScope`).

---

## 2. Public Components

### 2.1. NotificationController
The primary configuration owner and state manager.

```dart
final controller = NotificationController(
  queues: {...},
  channels: {...},
  strictChannelLookup: false,
  maxHistoryEntries: 100,
  logLevel: LogLevel.info,
);
```

#### Dispatch & Triage Methods
- `show(AppNotification notification, {QueuePosition? targetPosition})`:
  Enqueues a notification into the system. Returns the assigned notification.
- `tryShow(AppNotification notification, {QueuePosition? targetPosition})`:
  Safely attempts to show a notification, returning `null` if rejected due
  to capacity limits.
- `dismiss(AppNotification notification, {DismissReason? reason})`:
  Programmatically dismisses an active or queued notification.
- `dismissAll({DismissReason? reason})`:
  Dismisses all active notifications across all queues.
- `dismissGroup(String groupKey, {DismissReason? reason})`:
  Dismisses all notifications in a group deck and purges backlog.
- `clearHistory()`:
  Clears historical notification logs.

#### Queue Stasis Methods
- `pauseQueue(QueuePosition position)`:
  Freezes countdown timers for all notifications in the specified queue.
- `resumeQueue(QueuePosition position)`:
  Resumes countdown timers for all notifications in the specified queue.
- `pauseAll()`:
  Freezes countdown timers across all queues simultaneously.
- `resumeAll()`:
  Resumes countdown timers across all queues simultaneously.
- `isQueuePaused(QueuePosition position)`:
  Returns `true` if the specified queue is currently in stasis.

#### Observability & Teardown
- `events`:
  Broadcast stream of `NotificationEvent` instances emitting lifecycle updates
  (`NotificationQueued`, `NotificationDismissed`, `NotificationTapped`,
  `NotificationRelocated`, `NotificationReordered`, `QueueOverflowed`,
  `NotificationSnoozed`, `NotificationPinned`, `NotificationGroupExpanded`,
  `QueuePositionRelocated`).
- `dispose()`:
  Disposes controller, cancels timers, and closes the event stream.

### 2.2. NotificationScope
Widget tree scope injector for attaching `NotificationController` to the
overlay surface.

- `NotificationScope({required controller, required child, bool useRootOverlay = true})`:
  Injects `NotificationController` and binds `NotificationOverlay`. When
  `useRootOverlay: false`, notification portals attach to the nearest ancestor
  `Overlay` instead of the root window, enabling local viewport scoping and
  sub-window boundary containment.
- `NotificationScope.of(context)`:
  Looks up the nearest `NotificationController` in the widget tree hierarchy.

---

### 2.3. AppNotification
Immutable data payload intent.

- `id`: Unique notification identifier (autogenerated if omitted).
- `message`: Primary body text.
- `title`: Optional headline title text.
- `channelName`: Target channel identifier (e.g. `'info'`, `'success'`).
- `priority`: Priority tier for triage preemption (`low`, `normal`, `high`,
  `critical`).
- `action`: Interactive button action (`NotificationAction.button(...)`).
- `tapBehavior`: Primary card tap intent (`TapToDismiss`, `TapToAct`,
  `TapToExpand`, `TapDisabled`).
- `duration`: Custom auto-dismiss duration overriding channel defaults.
- `groupKey`: Group key string for deck aggregation.

---

### 2.4. NotificationQueue
Declarative configuration object for spatial layout and stacking behavior.

- `position`: Spatial screen anchor (`QueuePosition`).
- `style`: Visual layout archetype (`FilledQueueStyle`, `OutlinedQueueStyle`,
  `FlatQueueStyle`).
- `dragBehavior`: Gesture interaction strategy (`Dismiss`, `Reorder`,
  `Relocate`, `ReorderAndRelocate`, `Disabled`).
- `longPressDragBehavior`: Secondary gesture strategy triggered on card
  long-press.
- `groupingBehavior`: Grouping deck rules (`QueueGroupingBehavior`).
- `permanentRelocation`: Permanent redirection target (`QueuePosition?`)
  rerouting all incoming notifications.
- `maxStackSize`: Maximum concurrent notifications allowed in the queue.

#### Queue Drag Behaviors (`QueueNotificationBehavior`)

##### 1. Spatial Egress
- `Dismiss({egress, dismissThreshold, escapeVelocity, ...})`:
  Directional swipe-to-dismiss with card-centric egress paths, dual thresholds,
  angular tilt, and reveal underlays. Parameters: `egress`, `dismissThreshold`,
  `escapeVelocity`, `enableTilt`, `showUnderlay`, `dismissIcon`, `dismissColor`.

##### 2. Spatial Movement (Reorder & Relocate)
*Note: In `v0.7.x`, spatial movement is exposed via separate classes. In
`v0.8.x`, these converge into a single unified spatial movement behavior.*
- `Reorder({thresholdInPixels, springPhysics})`:
  In-queue live stack reordering with gravity-well hysteresis.
- `Relocate.to(positions, {permanent, springPhysics})`:
  Cross-queue spatial drag relocation with insertion previews.
- `ReorderAndRelocate.to(positions, ...)`:
  Hybrid interaction: reorders locally or relocates across queues when dragged
  past escape threshold (`escapeThresholdInPixels`).

##### 3. Retention & Card Actions (@experimental)
*Note: Drag-to-action is experimental in `v0.7.x` and evolving into a dedicated
action/retention model (header action pills, context menus, reveal actions).*
- `Pin()`: Pins the card to prevent auto-dismiss and gesture dismissals.
- `Snooze({duration})`: Temporarily shelves the card for later re-display.
- `CustomAction({actionName})`: Dispatches a developer-defined action event.

##### 4. Interaction Disabled
- `Disabled()`: Disables all drag interaction gestures.

#### Dismiss Egress Strategies (`DismissEgress`)
- `DismissEgress.horizontal({allowLeft = true, allowRight = true})`:
  Horizontal exit vector (left or right). Default egress policy.
- `DismissEgress.natural()`:
  Screen-outward exit direction determined by queue anchor position.
- `DismissEgress.outward()`:
  Outward exit toward closest screen boundary.
- `DismissEgress.cross()`:
  Inward exit across screen toward the viewport center.
- `DismissEgress.any()`:
  Omnidirectional 360-degree exit in any gesture vector.

---

### 2.5. NotificationChannel
Semantic category definitions for notifications.

- `name`: Unique channel identifier string (e.g., `'success'`).
- `theme`: Semantic visual styling via `NotificationThemeData` (`accentColor`,
  `backgroundColor`, `foregroundColor`, typography, icon theme).
- `defaultIcon`: Default icon widget.
- `position`: Default target `QueuePosition` for notifications routed through
  this channel.
- `defaultDismissDuration`: Default auto-dismiss timeout duration.

---

### 2.6. Invariant Engine & Stasis Types

#### `TimerPauseReason`
Typed enumeration of valid pause triggers:
- `drag`: Pointer pan or drag gesture active.
- `hover`: Pointer hovering over card bounds.
- `touchHold`: Mobile press-and-hold contact.
- `expanded`: Card expanded into extended detail view.
- `contextMenu`: Desktop secondary click or context menu open.
- `pinned`: Explicitly marked as pinned.

#### `NotificationTimerScope`
`InheritedWidget` propagating queue-level stasis down the widget tree:
- `NotificationTimerScope.isEnabled(context)`:
  Reactive subscription lookup.
- `NotificationTimerScope.isEnabledNonSubscribing(context)`:
  Non-subscribing lookup for `initState()` and invariant assertions.
